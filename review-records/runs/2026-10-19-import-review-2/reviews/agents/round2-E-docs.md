tools/docs-site, mkdocs.yml, THIRD_PARTY_NOTICES.md. I checked every claim against the source at HEAD.

## Findings

### E2-1 doc-wrong, medium: the CHANGELOG says Folia allows register/unregister on a region thread
- Location: `CHANGELOG.md:89-90` ("throw `IllegalStateException` off the main thread (on Folia, off a region or the
  global region thread)").
- What is wrong: a6e97500 (B-4) made `register` and `unregister` refuse every thread that ticks a region.
  `paper/.../CommandLib.java` `requireGlobalThread` throws when `FoliaCommandScheduler.onRegionThread()`. On Folia,
  only the global region thread and the server thread that enables plugins pass. `docs/execution.md:173-174` and
  the design doc already say this. Only `refresh`/`refreshAll` accept any region thread.
- Fix: "... off the main thread (on Folia, off the global region thread; region threads are refused too)".

### E2-2 backcompat, medium: the CHANGELOG leaves out the removed Forge allowLogging overloads
- Location: `CHANGELOG.md`, the "Messages" breaking-change section (lines 58-72).
- What is wrong: 0.17.2's Forge `CommandContext` had `sendMessage(String, boolean allowLogging)`,
  `sendMessage(ITextComponent, boolean)`, `sendWarn(String, boolean)` and `sendFailure(String, boolean)`
  (`git show 0.17.2:forge/src/main/java/net/kunmc/lab/commandlib/CommandContext.java`). c9cad70a (C-4) deleted
  them, so a Forge mod that calls them no longer compiles. Only `sendSuccess(.., boolean)` remains, renamed to
  `broadcastToOps`. The CHANGELOG lists `sendComponent` and `addPreprocess(Consumer)` but not these overloads.
  The other round-1 removals (CommandOption constructor, the paper-testing withers, FakeSender/extension behaviour,
  Paper ChatColorArgument, variadic and annotation rejections) only touch APIs that are new in 0.18.0, so leaving
  them out is correct.
- Fix: add "Forge / NeoForge / Fabric: `sendMessage(.., boolean)`, `sendWarn(.., boolean)` and
  `sendFailure(.., boolean)` are removed. `sendSuccess(message, boolean)` remains; its flag broadcasts to operators."

### E2-3 doc-wrong, medium: testing.md describes `denyPermissions` as "all but these" on every artifact
- Location: `docs/testing.md:195` ("`permissions(nodes...)` (only these nodes), `denyPermissions(nodes...)` (all but
  these)").
- What is wrong: after a9b45b26 / dc6a06ff (D-15), on spigot-, paper- and common-testing `permissions` replaces the
  granted set and `denyPermissions` adds to the denied set. The two combine, and a denied node wins.
  `FakeSender.player("A").permissions("x").denyPermissions("x.y")` grants only `x`, not everything but `x.y`.
  On velocity-testing and modded-testing, each instance call replaces the whole answer, so the last call wins.
  The modded builder combines the two lists. The page describes only the replace behaviour. Unifying the
  behaviour is still pending (E-21 in triage), so the page should at least describe each artifact correctly.
- Fix: describe both behaviours. On common/spigot/paper they combine and a deny wins; on velocity and on modded
  instances the last call replaces. Or unify the code first (E-21) and then document one rule.

- Fix: add "(except `velocity-testing`, see [testing](testing.md))".

### E2-5 doc-wrong, low: the CHANGELOG says the Velocity target does not cover PlayerArgument

### E2-6 doc-wrong, low: arguments.md says modded fake sources have no level
- Location: `docs/arguments.md:370` (MessageArgument, modded column: "selectors are resolved only with a level,
  which the fake sources lack").
- What is wrong: since f90e8cfa every modded-testing source is in a level. `FakeSender.createSource` passes
  `server.overworld()`, and the tester stubs a mock overworld unless `withLevel` adds one. The stated reason is no
  longer true. Unconfirmed: whether an operator's `@a` in a MessageArgument now resolves under the tester (I did not
  run a modded build). Lines 81 and 357 say the levels are only those added with `withLevel`; that is also
  incomplete.
- Fix: check with a quick op-sender test, then state the actual behaviour. Mention the default mock overworld in the
  WorldArgument row and the testing.md "Fake world state" row.

### E2-7 doc-wrong, low: rich-text-messages.md still lists modded's `sendMessage(Component, boolean)`
- Location: `docs/design/rich-text-messages.md:247-248` ("Kept: ... modded's `sendMessage(Component[, boolean])`").
  The "Removed APIs" table (241-245) also leaves out `sendComponent` and the modded allowLogging overloads.
- What is wrong: c9cad70a removed `sendMessage(Component, boolean)`. Modded now has `sendMessage(Component)` and
  `sendSuccess(Component, boolean broadcastToOps)` (line 182 of the same doc is correct). 2b3561dd removed
  `sendComponent`.
- Fix: "modded's `send*(Component)` and `sendSuccess(Component, boolean)`". Add rows for `sendComponent` (replaced by
  `sendMessage(C)`) and the modded `(.., boolean)` overloads.

### E2-8 doc-wrong, low: the extension refusal is documented for three artifacts; modded refuses too, common-testing does not
- Location: `docs/testing.md:182-184`.
- What is wrong: 33f166de also made modded-testing's `CommandLibExtension` refuse injection outside a test method
  context (`@BeforeAll`, constructors). The page names only spigot, paper and velocity.
  `common-testing/.../CommandLibExtension.java` has neither refusal. It stores the tester in whatever store the
  context gives, so a `@BeforeAll` injection there still shares one tester across the class. That is the bug the
  other four fixed (test-util-bug; outside my area but found while checking this line).
- Fix: in the docs, say the refusals apply to every artifact except common-testing (or add the same guard to
  common-testing and say "every artifact").

### E2-9 doc-wrong, low: the skill says EnchantmentArgument / PotionEffectArgument need MockedStatic on spigot-testing
- Location: `plugins/commandlib/skills/commandlib/references/testing.md:148-149`.
- What is wrong: on Spigot both are NMS-backed (`NMSArgumentEnchantment` / `NMSArgumentMobEffect`), and
  spigot-testing mocks them. `docs/arguments.md:360-361` lists them as "mock", and line 84 of the same skill file
  calls `EnchantmentArgument` NMS-backed. The sentence leads generated tests to add static mocks they do not need.
- Fix: delete the sentence, or replace it with the "static" rows of the catalog (`SoundArgument`, `BiomeArgument`,
  `AttributeArgument`, `EntityTypeArgument` via `Registry`).
